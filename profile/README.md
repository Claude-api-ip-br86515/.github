<p>「出口重复率低」这句话在销售页上人人都写，但你没法验证。可行的办法是自己做一次小规模对照：把账号分成三组，分别走共享机房、共享住宅、独享住宅三种出口，其他条件全部锁死，跑七天，把重复率、验证触发次数、开通耗时和中断次数记下来。这篇给的就是这套实验的完整设计——分组怎么分、指标怎么采、数据怎么读、结论怎么落到内部系统的接口上。适合号池体量大、正打算把开号流程接进自家后台的团队先做一次这样的验证再采购。</p>

<h2>一、实验设计：只改出口这一个变量</h2>
<p>对照实验的全部难点在于控制变量。很多人做完对比，发现结论站不住，原因是同时换了出口、换了客户端版本、换了操作时段，最后说不清是哪一项起的作用。所以第一步是把变量锁死：同一批注册时间的账号、同一个客户端版本、同一套操作脚本、同一个时间段执行。</p>
<p>唯一允许变化的因素是出口类型。三组各十个号，样本不大但足够看出趋势。观察期七天，前两天只做开通和连通性，后五天跑真实业务动作。这个时长的选择是因为很多出口问题在头两天看不出来，要跨过周末和工作日的流量差异才显现。</p>

<h2>二、三组怎么设，指标怎么采</h2>
<p>分组的关键是让三组的「起点」尽量一致。账号的注册时间集中在同一个上午，注册时用的资料类型相同，避免某一组因为资料差异被额外校验。这一步不做，后面的数据全是噪声。</p>

<h3>采集方式：能自动就别手工</h3>
<p>四个指标里，三个可以自动采：出口 IP 每次请求记录一条，验证弹窗用页面特征匹配后截图留档，中断次数从网关日志按状态码聚合。只有「开通耗时」需要人工记，从下单到拿到可用凭据的时间戳。</p>
<p>采集频率按每 30 分钟一次，一天 48 个采样点。七天下来每组约 336 条记录，量不大，用一张表就能装下，不需要上监控系统。</p>
<h3>重复率怎么定义</h3>
<p>这是最容易被含糊过去的指标。定义要落到可计算：在观察期内，同一组内出现的不同出口 IP 数量，除以该组的采样总次数，得到的是「IP 复用度」；反过来，不同账号之间出现相同出口 IP 的次数，除以账号两两组合数，得到的是「撞车率」。采购时说的「重复率低」，通常指后者的补集。</p>
<p>再补一个维度：出口 IP 所在的 /24 网段重复情况。有些服务商给你十个不同的 IP，但全在同一个 /24 里，平台看来还是一段地址。这一项要单独统计。</p>

<h2>三、第一到三天：开通与连通先过关</h2>
<p>头两天的数据主要看两件事：能不能按时拿到凭据，拿到之后能不能稳定连通。这两项不过关，后面五天的数据没有意义。</p>
<h3>开通耗时</h3>
<p>记录从下单到凭据可用的分钟数。自助开通通常在几分钟到半小时，人工配置的可能要几小时到一天。如果内部系统要接自动化开号，这个指标直接决定你的队列设计——开通慢的方案，必须做异步排队，不能同步等。</p>
<h3>连通性与首字节时间</h3>
<p>每组每 30 分钟发一次轻量请求，记录状态码和首字节时间。判定阈值：成功率低于 98% 说明该组有不稳定时段；首字节时间的 P95 超过 800 毫秒，日常对话会有明显停顿感。这两项在三组之间的差异，往往比预想的小——机房出口在纯连通性上经常不输住宅，差别在后面的环节。</p>

<h3>怎么读这张表</h3>
<p>注意 A 组的一个反直觉现象：机房出口的链路质量其实最好，中断次数最低，但验证触发最多。这说明中断和验证是两件独立的事，前者看链路，后者看出口的身份属性。选型时如果只测延迟和丢包，会得出「机房更好」的错误结论。</p>
<h3>B 组的波动为什么大</h3>
<p>共享住宅出口的表现高度依赖同一时间还有谁在用。你的号可能和几十个陌生账号共用一个出口，对方的操作强度直接影响到你。这类出口在低峰时段表现接近独享，高峰时段明显下滑。如果业务集中在某个时段，必须按那个时段的数据做判断。</p>

<h2>五、结论怎么落到内部系统的接口上</h2>
<p>实验做完不是写个报告就结束，要把结论变成系统里的约束。三个地方值得直接落下去。</p>
<h3>开号队列按开通耗时设计</h3>
<p>实测开通耗时如果是十分钟，队列就按十分钟一个批次设计，不要按一分钟。同步等待会在批量开号时把接口拖死。</p>
<h3>出口分配做成一对一绑定</h3>
<p>把账号 ID 和出口 ID 的绑定关系写进数据库，一个账号只允许一条出口。这条约束一旦落到代码里，「反复换线路」这件事就从流程上消失了，也省掉了大量人工核对。</p>
<h3>把重复率做成上线前的门禁</h3>
<p>新采购的线路在接入前跑一次批量查询，统计 /24 段集中度。超过阈值就退回，不进生产。这个门禁比事后排查便宜得多。</p>

<h2>常见问答</h2>
<h3>样本只有十个号，结论可信吗？</h3>
<p>答：看趋势够用，做精确统计不够。十个号的样本能看出组间差异的方向和量级，尤其验证触发这种差异明显的指标。如果要给出置信区间，每组至少三十个号，观察期延长到两周。</p>
<h3>为什么机房出口的中断次数反而更低？</h3>
<p>答：机房链路的带宽和稳定性通常优于家庭宽带，这是事实。但机房段的身份属性和住宅不同，平台侧的校验会更频繁。中断看链路质量，验证看出口身份，两个维度要分开评估。</p>
<h3>撞车率和重复率是一回事吗？</h3>
<p>答：不完全是。重复率通常指同一 IP 被多少账号共用，撞车率指你的账号之间是否落到同一 IP。采购时要问清是哪一个，更严谨的做法是自己按 /24 段统计集中度，这个口径最接近平台侧的观察方式。</p>
<h3>实验结果能直接推广到其他服务商吗？</h3>
<p>答：不能。结论只对被测的那批线路成立。但实验方法可以复用，换一家服务商时按同样的分组和指标再跑一遍，两天就能得出可比的数据。</p>
